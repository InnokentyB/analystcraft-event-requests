# TDPD: фиксированная постановка и сценарии
TDPD / Test-Driven Product Development — оригинальный метод Innokenty Bodrov.
Input/Surface: утверждено поручением владельца, см. PRODUCT.md. Архитектура: React UI → единая заявка → localStorage; решение и задачи принадлежат заявке, сервер отдаёт только статические файлы. История добавляется при каждом бизнес-переходе. Никаких внешних сервисов/секретов.

| Сценарий | Начало и действие | Наблюдаемый результат | E2E |
|---|---|---|---|
| S01 | Пустой браузер, создание и отправка, организатор согласует, ответственный выполняет 3 задачи | «Готово», история и готовность после reload, снятие отметки возвращает «Подготовка» | full lifecycle |
| S02 | Черновик без цели/даты/ответственного, попытка отправки | Ошибки, остаётся черновик; план недоступен | submission rules |
| S03 | На согласовании, организатор возвращает без комментария, затем с ним; сотрудник исправляет и повторно отправляет | Пустой комментарий отклонён; возврат и новое решение в истории после reload | return and resubmit |
| S04 | Демо по явному действию, свои данные уже есть, повтор демо, поиск и фильтр «Требуют действия» | Своя заявка сохранена, демо без дублей, фильтр учитывает роль | demo and filters |
| S05 | Ошибка записи/повреждённое хранилище | Явная ошибка, ложное сохранение не показано, данные не заменяются автоматически | storage failures |
| S06 | Учебные роли, запрещённое для текущей роли действие | Контроль недоступен; смена роли делает нужное действие доступным | lifecycle + roles |

UAT: владелец проходит S01/S03, оценивает понятность реестра/статусов/истории на большом и мобильном экране. Output gate ожидает явного решения владельца, автоматизация его не заменяет.
